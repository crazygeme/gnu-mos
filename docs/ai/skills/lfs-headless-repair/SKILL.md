# LFS 无窗口运行与修复

## 启动时收集凭据

加载技能后的第一条回复必须询问本机 sudo 密码、客户机登录用户名及密码。即使上下文中包含密码，也不得直接复用；应先请求本次运行所需的凭据。允许使用免密 sudo 或 SSH 密钥，并接受相应说明。

建议提问：

> 请提供本次运行的本机 sudo 密码，以及客户机登录用户名和密码；如使用免密 sudo 或 SSH 密钥，请注明。

收到答复前，只能进行不需要凭据的只读检查。凭据仅用于本次认证，不得写入技能、项目文件、脚本、日志、报告或版本控制记录。优先通过工具的标准输入或交互式认证提示传入密码，避免将密码放入命令行参数、命令历史和打印输出。

## 工作范围与约束

- 以当前项目根目录为工作目录，先读取适用的 `AGENTS.md`，检查工作区修改并保留已有修改。
- 根据任务自主完成诊断、实现和验证。收到凭据后，不重复询问已授权的工具使用或常规修复操作；仅在缺少必要信息或存在实际授权边界时提问。
- 自行编写命令行，不在主机桌面弹出 QEMU 窗口。通过本地 VNC、SSH、串口日志、QEMU monitor 和 GDB 访问客户机。
- 明确调用本技能即授权执行当前修复任务所需的代码编译、包构建及镜像安装，无需再次请求编译许可。仅构建与任务相关的包；当前任务另有禁止编译或安装的限制时，遵循该限制。
- 测试代码和测试编译命令不得使用 `pthread` 或 `-Wextra`。需要并发时，可根据测试目标使用 `fork` 或 `clone`。
- 不修改任务范围之外的应用功能或系统配置。

## 启动与连接

先检查 QEMU 进程、镜像占用、监听端口、`lfs-tap0` 和 dnsmasq 状态。使用现有项目启动器，保留其内存、设备和网络配置。检查项目当前配置后选择可用端口；以下命令适用于支持 EGL 的图形环境：

```sh
MOS_AUDIO_BACKEND=none ./lfs run -- \
  -display egl-headless \
  -vnc 127.0.0.1:9 \
  -monitor unix:/tmp/gnu-mos-monitor.sock,server=on,wait=off \
  -gdb tcp:127.0.0.1:12349
```

VNC 显示号 `9` 对应 TCP 端口 `5909`。VNC 和 GDB 仅绑定回环地址；不向外网开放调试端口。若 EGL 不可用，应先检查渲染节点及 QEMU 图形设备配置，再选择兼容的无窗口显示方式。

使用 `ip`、dnsmasq 配置和 DHCP 租约确认客户机地址，不假定地址恒定。SSH 主机密钥应使用专用 known-hosts 文件，并核对变更。启动图形应用时使用客户机桌面的 `DISPLAY` 和实际会话 `DBUS_SESSION_BUS_ADDRESS`，只提取所需环境字段，避免打印完整进程环境。

通过 VNC 获取登录界面和应用截图，不将窗口显示到主机桌面。Microsoft Edge 的入口为 `/usr/bin/microsoft-edge`；检查入口、厂商启动脚本、动态依赖和运行参数后再修改。

## 诊断与修复

结合应用标准错误、客户机进程状态和 `.workspace/<arch>/krn.log` 区分应用、依赖、图形、网络与内核故障。对内核异常，可使用仅绑定回环地址的 QEMU GDB 服务获取异常位置、寄存器和调用栈。保留能够说明故障原因的最小证据。

MOS 源码仅在 `.workspace/sources/mos` 中直接修改，不使用 `../mos`。其他软件通过包配置、构建参数、依赖或独立补丁修复；补丁须对配置的准确源码归档进行全新解压，并通过 `patch --dry-run` 验证。缺失依赖必须补齐，不通过禁用组件规避。

需要重编译的修改递增相应 `src/packages/<package>/version` 整数。不得手工修改现有 `.done` 标记的版本。使用项目构建入口执行任务所需的编译，让构建过程记录成功版本。

需要永久保留的启动包装脚本和系统配置写入包 postscript 或 `src/sysroot`。`./lfs setup` 负责执行 postscript 并复制 sysroot，不向其添加包完整性、可执行格式或单文件检查。若应用需要降低隔离能力才能运行，应确认对应平台限制，并在交付中说明实际启用的参数及影响。

## 镜像与网络生命周期

执行 `./lfs setup`、挂载镜像或运行文件系统修复前，必须确认使用该镜像的 QEMU 进程已退出。客户机关机命令返回不能作为 QEMU 已退出的证据。不得对运行中的镜像执行安装或离线文件系统修复；临时 loop 设备应在操作结束后解除。

遇到 `lfs-tap0` 创建失败时，先确认是否存在活动客户机及接口占用。存在活动实例时应复用或明确报告占用，不删除其网络。仅在确认没有活动客户机、且资源属于本项目后，清理残留的 TAP、dnsmasq、PID 文件和对应 NAT/FORWARD 规则。

终止 dnsmasq 前核对 PID 对应的实际命令、接口和 PID 文件，防止 PID 复用。仅删除匹配 LFS 子网和接口的规则，不清空防火墙，不影响其他 VPN、容器网络或 SSH 会话。清理后验证网络能够创建并在退出时释放。

## 验证与交付

验证修复对应的实际客户机行为，并执行必要的回归测试。浏览器验证包括 HTTPS 页面加载、JavaScript、Canvas、正常关闭和重新启动；优先验证原有用户配置，不删除个人资料。使用临时配置时，应另行检查原有配置的启动行为。

检查最新内核日志是否出现异常，并检查修改文件的差异和格式。截图及诊断产物可保存到 `.workspace/<arch>/logs`，不得包含凭据。

交付中说明修复结果、验证范围、当前客户机是否运行、连接方式及实际技术限制。按任务需要保留客户机或关闭本次实例；临时调试连接应清理。结束前核对进程状态，不将启动成功描述为持续运行。
